# Trigger

`asgard-ai.com/v1alpha1`, kind `Trigger`, plural `triggers`, namespaced.

| field | type | required | default | constraints | what it is |
|---|---|---|---|---|---|
| `spec` | object | **required** |  |  |  |
| `spec.cron` | object | **required** |  |  | when triggerClass is cron |
| `spec.cron.schedule` | string | **required** |  |  | Schedule is a standard five-field cron expression or an @descriptor. It is copied verbatim into the derived CronJob's spec.schedule, so the grammar is exactly whatever that field accepts. Deliberately carries no Pattern, matching batch/v1 CronJob, whose published schema for spec.schedule is a bare string: cron grammar is not expressible as a regex without hand-copying robfig/cron's parser, and the regex that used to live here had copied it wrong in both directions — rejecting lists ("0 8,13 * * *"), ranges, step-on-range, month/day names and every @descriptor, all of which the API server accepts, while admitting "*/0 * * * *", which it does not. The gate is a cron.ParseStandard() parse, run where the API server runs its own: synchronously on write, by the asgard-kube-admission validating webhook, and again at the public API boundary so the caller gets the message directly. |
| `spec.cron.timeZone` | string | **required** |  |  | TimeZone |
| `spec.entrypoint` | object | **required** |  |  | workflow entrypoint setting |
| `spec.entrypoint.entry` | string | **required** |  |  | workflow entrypoint |
| `spec.entrypoint.workflow` | string | **required** |  |  | workflow to be triggered |
| `spec.message` | string | - |  |  | Message is what this Trigger says to the agent when it fires — the scheduled equivalent of a person opening the chat and typing it. It becomes the first message of the conversation the firing starts, and reads as the user's own, because a Trigger acts on behalf of whoever configured it. Optional, and usually left empty. By the time someone configures a Trigger they have normally already written the task at length in the workflow's prompt, so demanding a message here invites the reasonable question "didn't I just say all that?" — leaving it blank means "send something sensible on my behalf". Deliberately has NO kubebuilder default. A default is applied at admission and written into the stored object, which would (a) freeze today's wording into every existing Trigger, unchangeable later, and (b) show the user words they never typed. The dispatcher supplies the fallback instead, so the wording ships with an image and the CR stays honest about what was actually configured. |
| `spec.triggerClass` | string | **required** |  | one of `cron` | TriggerClass is the kind of source that fires a Trigger. Only cron remains. The specialized classes — google-sheet, google-drive, google-mail, onedrive, onedrive-workbook and imap — were removed: each one had asgard decide how to read a customer's data source, which meant inventing conventions the customer had to follow (a ready-flag column, a boundary column, mime allowlists, IMAP search criteria) and which in practice they could not hold to. A cron Trigger fires the workflow and the agent reads whatever it needs from inside its sandbox, so the shape of the data is the customer's business again and one firing can work through a whole batch instead of a single row. |
