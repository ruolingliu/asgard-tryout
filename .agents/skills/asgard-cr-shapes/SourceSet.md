| `spec.contextIndex` | object | - |  |  | ContextIndex turns this SourceSet into a knowledge-graph-backed one: when set, the platform provisions a scheduled agent that walks the volume and builds — then incrementally refreshes — a knowledge graph inside it, under the ".context-index" directory. Agents that later mount this SourceSet, typically read-only, can then query that graph instead of reading every file. Presence is the whole switch. Setting it provisions the derived Workflow, SandboxBlueprint and Trigger; clearing it back to nil tears all three down and renames the volume's ".context-index" directory aside as ".context-index_bak_<timestamp>" rather than deleting the graph — that graph may represent hours of model time, and from here there is no way to tell a change of mind from a mis-click. To pause the refresh schedule while keeping both the graph and this configuration, set the label asgard-ai.com/context-index-suspend to "true" instead of clearing this field. |
| `spec.contextIndex.completionModelName` | string | - |  |  | CompletionModelName is the CompletionModel CR, in this namespace, that the indexing agent talks to. Empty means the platform's fast builtin. Indexing is a long, document-heavy job, so the choice is worth exposing — but not worth demanding. |
| `spec.contextIndex.cron` | object | **required** |  |  | Cron is when the graph is refreshed. Required: an index that never refreshes silently rots against a volume people keep uploading to, and nobody finds out. |
| `spec.contextIndex.cron.schedule` | string | **required** |  |  | Schedule is a five-field cron expression or an @descriptor; see TriggerCronSpec for why this is not regex-validated here. |
| `spec.contextIndex.cron.timeZone` | string | **required** |  |  | TimeZone the schedule is evaluated in, as an IANA name (e.g. "Asia/Taipei"). |
| `spec.contextIndex.effort` | string | - |  | one of `low`, `medium`, `high`, `xhigh`, `max`, `auto`, `disabled` | Effort is the reasoning depth for the indexing agent. Empty leaves the agent's own default. "disabled" is not a depth at all: it declares that the chosen model rejects the reasoning-effort parameter outright, so nothing is sent — needed because such a model fails on EVERY value, including the default the agent would pick by itself. |
| `spec.contextIndex.includePaths` | array | - |  |  | IncludePaths narrows the index to these folders of the volume. Absent or empty indexes the whole volume. The point is the common case of a Syncer bringing in far more than the knowledge: a whole git repository when only its docs/ folder matters. Each entry is one folder, relative to the volume root and written like a Syncer's destinationPath — "repos/handbook/docs/": no leading '/', a trailing '/', no '.' or '..' segment. It includes everything beneath it. - LITERAL folder names, never globs: "*" matches only a folder named "*". - Several entries are a union; one beneath another is redundant, not an error. - A folder that does not exist yet is not an error either. It contributes nothing until something is synced into it, and the indexing run reports it. - The scope only ever narrows. Ignore files inside an included folder — a synced repository's own .gitignore — still apply. - Narrowing does not remove what an earlier, wider index already holds. To start over, clear contextIndex and set it again: the old graph is renamed aside, and the next run builds from scratch. The operator hands this list verbatim to the indexing sandbox, which turns it into the graph builder's ignore rules. That translation deliberately lives in the sandbox image, next to the graph builder version whose rule dialect it targets. The '.' / '..' rule checks whole segments, unlike destinationPath's substring check, so a folder legitimately named "Acme Inc." stays expressible. |
| `spec.contextIndex.prompt` | string | - |  |  | Prompt is APPENDED to the platform's own instructions for the indexing agent; it does not replace them. This is where domain knowledge goes: what these files are, which of them matter, and what the graph is going to be asked about later. Optional, and normally empty to begin with. The intended way to fill it is backwards: run the index, ask the agent questions it answers badly, ask it why, and let it write down what it should have done instead. Demanding good instructions before anyone has seen the graph asks for a guess. |
